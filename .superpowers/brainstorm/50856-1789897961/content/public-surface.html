How should a package's public surface be drawn?

Workspace top level. bespoke_story publishes ports and types; desk, cover and interview are private. Two plugins and a server depend on it, and bespoke_tools is reaching into desk — a violation.

A · Public components listed on the node

One box per package, as today. The contract is a line inside the node; the violating edge is labelled with the private component it reached. Smallest change — the view stays one node per package, so layout and drill-down are untouched.

B · Public components as ports on the boundary

Edges land on the component they actually use. Published components become small boxes on the package boundary, so a legal dependency visibly terminates at a port and the violation visibly bypasses one — the picture carries the architecture, not just a label. Costs a nested node in the view model, which is flat today.

C · Nothing new until you drill in

Top level unchanged. The violation is still red, as it already is today. Public components are marked only inside a package's own view. Cheapest, and keeps a six-package workspace uncluttered — but the one screen where the contract matters most doesn't show it.

All three keep the violating edge red — that part already works. The question is only how much of the contract the top level should carry.
